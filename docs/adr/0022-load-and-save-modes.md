# 0022. Load and save modes

- Status: accepted (the maintainer, 2026-11-13, with SACM-XMI-011 as Info)
- Date: 2026-11-13
- Matrix rows: LIB-COMPAT-001, LIB-COMPAT-007. This ADR takes over ADR 0013 amendment 1,
  settles how ADR 0017 W4 applies to strict save, and answers ADR 0015 amendment 1's
  request for codes.

## Context

D-STRICT defines two modes:
- strict, which means SACM 2.3 conformance;
- tolerant, which also accepts recognised variations, with warnings.

ADR 0013 amendment 1 made strict save validate. ADR 0015 and ADR 0017 left room for the
modes in `ReadOptions` and `WriteOptions`. The assurance-forge C++ library has `enum class
Mode { Strict, Tolerant }`, with `LoadOptions{mode = Tolerant}` and `SaveOptions{mode =
Strict}` (`io/options.h:17-43`).

Neither SACM 2.3 nor XMI 2.5.1 defines the two modes. SACM §2.2 asks only that a
conforming tool "be able to import and export XMI documents that conform with the SACM XML
Schema", and XMI §2.2.2 asks that a document be "equivalent to those generated by the XMI
Document production rules".

## Decision

- **One `xmi::Mode { Strict, Tolerant }`.** It is `#[non_exhaustive]` and has no default of
  its own.
  - `ReadOptions` defaults to `Tolerant`, and `WriteOptions` to `Strict`. Both are set with
    `with_mode`.
  - `ReadOutput::mode()` reports the mode the document was read in.
- **"Accepts" in D-STRICT means "reads without loss".**
  - Strict never applies a tolerance, that is, an interpretation the standard does not
    give, such as inferring a class from an element name. Where reading would need one,
    strict refuses, and the row that adds the tolerance gives the refusal its code.
  - Where the input can be held exactly as written, both modes read it, and the mode decides
    only the severity: an Error in strict mode, a Warning in tolerant mode.
- **Two read findings.** In this release both modes read and refuse the same inputs. Two
  findings are reported:
  - SACM-XMI-010: `xsi:type` is used (XMI 2.5.1 §9.5.2 rule 2g, "You may only use the XML
    schema instance type attribute if org.omg.xmi.useSchemaExtensions is true"; SACM sets no
    such tag).
    It is an Error in strict mode and a Warning in tolerant mode.
  - SACM-XMI-011: `xmi:version` is present and ignored (§7.5.3: the namespace identifies
    the version, and the `XMI` complexType declares no version attribute). It is Info in
    both modes. The standard is inconsistent here: rule 1a's prose, §7.6.3 and the §7.10.2
    example still mention a version attribute (defect D10). The attribute carries no model
    data, so nothing is lost (the maintainer, 2026-11-13).

  Each finding is one diagnostic per attribute, located at the attribute's name.
- **Strict save validates.** Strict `write` runs `validate` after the `NoRoot` check, and
  refuses on any Error with `WriteError::Invalid`. The refusal holds every Error, in
  `validate`'s order, and has no catalog code of its own; each diagnostic carries its own.
  Tolerant save does not validate and writes the document as it is held.
- **Reporting.** A validation refusal reports every Error, as ADR 0013 amendment 1 said. The
  writer's own representability checks still stop at the first failure (ADR 0017 W4).
- **Semver.** A new validation Error rule, or a new read diagnostic, in a minor release can
  make a strict save refuse, or a strict read report errors, where it did not before. This
  is not a breaking change, and the release notes list each such rule.
- **Codes for today's `Unsupported` defect refusals** (ADR 0021's second list):

**Differences from C++, one line each:**
- M1. `Mode` is `#[non_exhaustive]` with no default of its own; the defaults live in the
  options, as C++ field initialisers do.
- M2. `ReadOutput::mode()` is added; C++ `LoadResult` records no mode.
- M3. Strict save validates and refuses on any validation Error. C++ strict save does not
  validate, and refuses only preserved content, with SACM-XMI-006 (`xmi_writer.cpp:485-500`).
- M4. The refusal is `Err(WriteError::Invalid)`, holding the validation diagnostics, with no
  code. C++ returns `ok = false` with one SACM-XMI-006 (ADR 0011 X1).
- M5. `xsi:type` and `xmi:version` are reported (SACM-XMI-010; SACM-XMI-011, as Info). C++
  reads both silently, because it writes both.
- M6. Tolerant applies no tolerance until its own row adds one. C++ tolerant mode matches
  class names ignoring case and strips plurals (`xmi_reader.cpp:2216-2241`).
- M7. There is no `SaveOptions::namespace_uri` yet (ADR 0017 W6, LIB-COMPAT-011).

## Consequences

- A document with a validation Error, such as a nameless element, is written only in
  tolerant mode. Editors save drafts with `Mode::Tolerant`.
- A strict read of an EMF or C++ file reports an Error for each `xsi:type`, and an Info for
  each `xmi:version`, and still returns the document.
- Strict output is a document `validate` finds no Error in. It is schema-conforming once
  SACM23-VAL-020 checks ids read from files; the maintainer moved that row into M1, as the
  next slice.
- ADR 0013 amendment 1, ADR 0017 (the `WriteOptions` bullet, the check order and W4) and ADR
  0021 (its "come with the load modes" line) point here, and D-STRICT gains "(reads without
  loss)".

## Alternatives considered

- **Two enums, `LoadMode` and `SaveMode`.** Rejected: D-STRICT defines one pair of modes.
- **Strict save does not validate, as in C++.** Rejected by D-STRICT, which says strict save
  writes only valid models.
- **Tolerant read applies C++'s leniencies now** (case-insensitive class names, plural
  stripping). Rejected: each is a tolerance that needs its own row and test.
