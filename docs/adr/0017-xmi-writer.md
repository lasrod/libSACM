## Context

Export is the first step of M1's round trip. The assurance-forge C++ writer
(`libs/sacm/src/io/xmi_writer.cpp`, `io/xmi.h`, `io/options.h`) is the design reference where
the standard is silent (CLAUDE.md rule 6). This ADR states the writer as it stands and names
each difference from C++. What the reader does is in ADR 0015, ADR 0016 and ADR 0021.

## Decision

`sacm::xmi::write(document: &Document, options: &WriteOptions) -> Result<String,
WriteError>`.
- `WriteOptions` is empty for now; the save mode comes with LIB-COMPAT-001.
- `WriteError` (ADR 0011) has two variants, and neither has a catalog code:
  - `NoRoot`, a plain unit variant, so callers can match it exactly;
  - `UnrepresentableCharacter { element, character, attribute }`, which is
    `#[non_exhaustive]`. `attribute` is a `WriteAttribute`: `Id`, `NameLang` or
    `NameContent`, a `#[non_exhaustive]` `Copy` enum that later rows extend.
- `WriteError` is `#[non_exhaustive]`. Nothing a `Document` holds is refused. The name
  `Unsupported { element, reason }` (no code, `#[non_exhaustive]`) is reserved, and adding it
  back is additive: the first row that lets a `Document` hold content
  no row writes adds it back in the same slice (LIB-API-010).

**The output, byte for byte:**
- **Encoding and layout.** UTF-8 with no BOM, `<?xml version="1.0" encoding="UTF-8"?>`, LF
  line endings, two spaces per depth, `<x … />` (with a space before `/>`) for an element
  with no children, and a final LF.
- **The document element** carries `xmlns:sacm` and `xmlns:xmi`, and no `xmi:version`
  (amendment 3, SACM23-XMI-024). A document with one
  root writes that root as the document element. One with several roots writes an `xmi:XMI`
  wrapper as the document element, carrying the declarations, with the roots one level
  down.
- **Each element's attributes:** `xmi:type`, when the class is not known from the role
  (T1), then `xmi:id`, then `assertionDeclaration="<literal>"` on an Assertion whose
  declaration is not `asserted`. The default is omitted, as XMI 2.5.1 §9.4.1 says:
  "Properties whose values are the default values are not serialized".
- **Names.** An element's name is its first child: one `<name … />` in no namespace, with no
  `xmi:id` or type attribute, carrying `lang` and then `content`.
  - An absent field is no attribute, and an empty one is `=""` (ADR 0012).
  - A missing name gets no `name` child (ADR 0013).
  - An element whose only content is its name gets a start tag, the `name` line and an end
    tag.
- **Roots and children.** Roots are written as `sacm:<Kind>`, in document order. Children
  are written under their role name, with no prefix, in model order (ADR 0010 D2). The role
  is the one each element stores when it is inserted (ADR 0010 amendment 1), from the
  containment table in `model::containment`.
- **Escaping.** In attribute values, `&`, `<`, `>`, `"`, TAB, LF and CR are escaped.
  Everything else is written as UTF-8.

**Checks, in order.** The first failure is the result.
1. A document with no root fails with `NoRoot`.
2. Each element is checked in document order (`Document::elements()` pre-order), and all of
   an element's checks run before the next element's: its id, then its name's `lang`, then
   its name's `content`. The first character that is not an XML 1.0 `Char` fails with
   `UnrepresentableCharacter`.

**Departures from C++:**
- **T1. `xmi:type`, not `xsi:type`**, as XMI 2.5.1 specifies (§7.8.8, rule 2g; SACM sets no
  `useSchemaExtensions`), and no `xsi` namespace. C++ writes `xsi:type` and always declares
  `xmlns:xsi` (`xmi_writer.cpp:435-439, 459, 540`). Import accepts both. The maintainer
  confirmed this after a fuller analysis (2026-11-12):
  - every existing SACM file in the C++ corpus uses `xsi:type`, but that is EMF's default,
    which C++ adopted;
  - OMG's own ptc/22-03-13 has 350 `xmi:type` and no `xsi:type`;
  - a schema generated by the default XMI rules has no derived types, so `xsi:type` output
    would most likely not validate against the schema SACM clause 2 refers to;
  - interoperability does not decide it, because EMF-based tools need a namespace mapping
    anyway;
  - a `WriteOptions` switch can be added later without a break.

  The attribute is written only where the class is not known from the role (XMI 2.5.1
  §7.6.3). Rule 2g and production 2d, read literally, require it on every element. This is
  specification defect D11, and this crate takes the §7.6.3 reading, as C++ and EMF do.
- **T2.** A document with no root is an error. C++ writes an empty `xmi:XMI`, which its own
  reader refuses (`:529-549`).
- **T3.** Roots are written in document order (ADR 0010 D1). C++ writes AssuranceCasePackage
  roots first (`:543-548`).
- **T4.** Children are written in model order, not grouped by role (`:254-337`).
- **No `xmi:version`.** C++ writes `xmi:version="2.0"` on the document element
  (`metadata/namespaces.h:32` `kXmiVersion`, `io/xmi_writer.cpp:461, 542`); this crate writes
  none, as XMI 2.5.1 §7.5.3 decides (amendment 3, SACM23-XMI-024).
- **W1.** It returns `Result<String, WriteError>`, not `SaveResult { xml, diagnostics, ok }`
  (`options.h:58-62`; ADR 0011 X1). C++ never fills diagnostics on a successful save
  (`xmi_writer.cpp:482-556`).
- **W2.** There is no file function. C++ has `save_xmi_file` (`xmi.h:23-24`), which reports a
  failed file write as SACM-XML-001 (ADR 0015, ADR 0011 X2).
- **W3.** A character outside XML 1.0 `Char` is refused. pugixml writes C0 controls as
  `&#NN;`, which is not well-formed, stops at U+0000, and writes U+FFFE and U+FFFF raw
  (`pugixml.cpp:4021, 4048-4054`).
- **W4.** A refusal names the first element in document order. C++ lists every affected
  element (`xmi_writer.cpp:485-500`). The same rule is in ADR 0016 D3. ADR 0013 amendment 1
  names every affected element for strict save; the load and save modes ADR settles this.
- **W5.** The namespace constants stay crate-private. C++ makes them public
  (`metadata/namespaces.h:17-34`).
- **W6.** There is no option to export under another SACM namespace. C++ has
  `SaveOptions::namespace_uri` (`options.h:26-43`). This is deferred to LIB-COMPAT-001.
- **Names.**
  - C++ writes absent and empty fields alike (`xmi_writer.cpp:260-265`).
  - C++ always writes `<name>`, even for a missing name (`:255-256`).
  - pugixml writes `>` raw and TAB as `&#09;`, where this crate writes `&gt;` and `&#9;`;
    that is a difference in bytes only.

**Kept from C++:**
- The `sacm` and `xmi` prefixes, and every package kind written as a root.
- `xmi:id` from the element id. An id that is not an NCName is written as it is, until
  SACM23-VAL-020 makes it a validation error.
- Omitting the default `assertionDeclaration` (`xmi_writer.cpp:95-98`).

## Consequences

- Written output follows the XMI rules, with the type attribute placed by the §7.6.3
  reading (D11). It is not byte-identical to C++.
- Adding diagnostics to a successful write later would change the return type. That is
  accepted, because C++ shows no such case.

## Alternatives considered

- `xsi:type`, as C++ writes it. Rejected by the maintainer for XMI conformance.
- `write_to(impl io::Write)`. Not now: it would need an I/O variant, and bytes could reach the
  sink before a refusal is found. It can be added later.
- Writing an empty `xmi:XMI`. Rejected: the reader cannot read it back.

## History

- **2026-11-12, first decision.**
  - Names and non-default declarations were refused as `Unsupported` (T5), never dropped.
  - `xmi:version="2.0"` was kept from C++ (`namespaces.h:32`), on the reading that XMI was
    inconsistent about it.
- **Amendment 1, 2026-11-12 (slice 0026; SACM23-XMI-011, SACM23-XMI-012).**
  - Names are written.
  - `UnrepresentableCharacter` gained `attribute: WriteAttribute`. A plain string was
    rejected, because `"content"` would become ambiguous.
  - The reader rules for `name` now live in ADR 0021.
- **Amendment 2, 2026-11-13 (slice 0030; SACM23-XMI-017, LIB-API-010).**
  - Non-default declarations are written, which ends T5.
  - `WriteError::Unsupported` was removed before any release.
  - The writer's unreachable "held in no role" check became the stored role.
  - The reader rules for `assertionDeclaration` now live in ADR 0021.
- **Amendment 3, 2026-11-13 (ADR review; SACM23-XMI-024).** The maintainer decided to drop
  `xmi:version`. XMI 2.5.1 decides it: §7.5.3 says "identification of the XMI version is
  indicated by the presence of the XMI namespace declaration", production 1a has no
  version attribute, and the §7.5.3 `XMI` complexType declares none. Rule 1a's text, "An XMI
  element has XML attributes that declare namespaces and specify the version of XMI", is
  met by the namespace declaration itself, which is the attribute that specifies the
  version. "2.0" also contradicts
  the `20131001` namespace written beside it. A `WriteOptions` switch is added only if a
  real consumer needs it.
