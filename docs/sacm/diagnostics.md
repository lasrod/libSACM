# Diagnostics catalog

Machine-readable diagnostic codes emitted by the `sacm` crate. **Codes are stable API**:
once released, a code's meaning never changes and a retired code is never reused.

Every diagnostic carries: `code`, `severity` (info / warning / error), the matrix row
and clause it enforces, affected element ids, an optional source location
(line/column), and a human-readable message. See decision D-DIAG.

> **Status.** The codes below are adopted from the assurance-forge C++ SACM library (same
> author), so that the two implementations report the same finding with the same code.
> Tool-specific wording from that project ("Assurance Forge", ODE containers) has been kept
> where it explains the code. A row is *live* when its Meaning names the `Code::NAME`
> constant whose text is the row's code: the crate emits that code, and the row says which
> matrix rows emit it. A row naming no constant is *reserved*: the crate does not emit it
> yet. Where a live row describes more than the crate emits, it says which part is emitted
> and that the rest is reserved. A test (LIB-DIAG-002) checks that the live rows are
> exactly the crate's `Code` constants.

Adding a code: append the row here in the same change that adds its constant to the
crate, and name the matrix row that owns it.

## XML and security

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-XML-001 | Error | The input is not well-formed XML 1.0 with namespaces, is truncated, is not valid UTF-8 or UTF-16, declares ASCII but holds non-ASCII, or has a UTF-16 byte order mark but declares an encoding other than UTF-16, UTF-16LE or UTF-16BE. UTF-16 with a byte order mark is read. Fix: correct the XML at the reported location. `Code::XML_MALFORMED`, the code of `ReadError::Malformed` (LIB-SEC-002, LIB-SEC-005, SACM23-XMI-018). |
| SACM-SEC-001 | Error | The input has a DOCTYPE, which may declare entities; it is refused before it is read. Fix: remove the DOCTYPE, because SACM XMI does not need one. `Code::XML_DOCTYPE_REJECTED`, the code of `ReadError::Doctype` (LIB-SEC-001). |

## XMI structure

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-XMI-001 | Error | An interchange root (the document element, or an element child of the XMI element outside the XMI namespace) is not named as one of the twelve SACM package kinds, or the XMI element holds no root. Fix: make the document element, or each child of `xmi:XMI`, a SACM 2.3 package such as `sacm:AssuranceCasePackage` or `sacm:ArgumentPackage`; a single package needs no `xmi:XMI` element. `Code::XMI_INVALID_ROOT`, the code of `ReadError::InvalidRoot` and `ReadError::NoPackage` (SACM23-XMI-001). |
| SACM-XMI-002 | Error (strict) / Warning (tolerant) | Namespace URI is not a pinned SACM 2.3 namespace. |
| SACM-XMI-003 | Error (strict) / Warning (tolerant) | Unknown element; preserved in tolerant mode, rejected in strict mode. |
| SACM-XMI-004 | Info | An element has no `xmi:id`, which XMI 2.5.1 §7.6.1 makes optional (`use="optional"`). `xmi::read` reads it in both modes, a root or a child, with a generated id in the edit scheme `<snake_case kind>_<n>` that no `xmi:id` in the input holds, and reports one Info per element at its start tag, affecting the generated id. The generated id is an ordinary id: `xmi::write` writes it, and later edits generate above it. Nothing needs fixing. `Code::XMI_MISSING_ID` (SACM23-XMI-020, ADR 0024). |
| SACM-XMI-005 | Error (strict) | Containment role has an abstract declared type and the child carries no type attribute (`xmi:type`, or `xsi:type` on import). |
| SACM-XMI-006 | Error | Strict save refused: document contains preserved unknown content or compatibility-only data (LIB-COMPAT-003). |
| SACM-XMI-007 | Warning | External (cross-document) `href` reference is not supported; kept as opaque text in compatibility mode only. Reserved: until SACM23-XMI-027 reads cross-document links, `xmi::read` refuses a reference element whose `href` has a document part (such as `other.xmi#c9`) as `ReadError::Unsupported`, in both modes, and never drops it (SACM23-XMI-015, ADR 0026). |
| SACM-XMI-008 | Warning | Document declares a SACM revision other than 2.3; loaded in compatibility mode. Distinct from SACM-XMI-002, which means the namespace itself is unrecognized. |
| SACM-XMI-009 | Warning | The document's root is not a SACM interchange package, but SACM packages were found inside it (an ODE `DDIPackage`, say). A tolerant load reads the SACM out and states that the file does not conform, that content outside the SACM packages is not represented, and that saving writes conformant SACM rather than the original container. Strict refuses the document (SACM-XMI-001). |
| SACM-XMI-010 | Error (strict) / Warning (tolerant) | An `xsi:type` attribute is used; XMI 2.5.1 §9.5.2 rule 2g allows it only if `org.omg.xmi.useSchemaExtensions` is true, and SACM sets no such tag. The document is read as if it were `xmi:type`. Fix: write `xmi:type`. `Code::XMI_XSI_TYPE` (LIB-COMPAT-001, ADR 0022). |
| SACM-XMI-011 | Info | An `xmi:version` attribute on the `xmi:XMI` element or a root is present and ignored: the XMI namespace identifies the version (XMI 2.5.1 §7.5.3). Nothing is lost and nothing needs fixing. To silence it, remove the attribute, or save the document again with `xmi::write`, which does not write it. `Code::XMI_VERSION_IGNORED` (LIB-COMPAT-001, ADR 0022). |

## Identity and references

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-ID-001 | Error | Duplicate element ID: two or more elements in the input carry the same `xmi:id` (XMI 2.5.1 §7.6.1), whether elements, `name`s, or the `content`, `key` and `value` elements of a UtilityElement (ADR 0025), compared by `xsd:ID` value (XML white space around an NCName trimmed, SACM23-XMI-025; ADR 0024). `xmi::read` refuses the input, giving the location of every element that carries the repeated `xmi:id`. `Code::ID_DUPLICATE`, `ReadError::DuplicateId` (SACM23-VAL-001). Fix: give each element, `name`, `content`, `key` and `value` its own id, or leave out the id of a `name`, `content`, `key` or `value`. |
| SACM-ID-002 | Error | Invalid element ID syntax: an element's id is not an XML NCName (XMI 2.5.1 §7.6.1: `xmi:id` is an `xsd:ID`). `Code::ID_INVALID`. For a new element it is `EditError::InvalidId` (LIB-EDIT-001). For an id read from a file, on an element or on a `name`, `content`, `key` or `value`: an empty `xmi:id` is refused as `ReadError::InvalidId`; an NCName with XML white space around it is read trimmed (SACM-ID-004); and any other id that is not an NCName (such as `1c`, `a:b` or `a b`) is read as written and reported by `validation::validate`, so a strict save refuses the document (SACM23-VAL-020). A name's `xmi:id`, and the `xmi:id` of a `content`, a `key` or a `value` in one (ADR 0025), that is not an NCName is reported on the element that owns it. Fix: use a name that starts with a letter or `_` and has no spaces or `:`, or leave the id out to have one generated. |
| SACM-ID-003 | Error | Duplicate `gid` (clause 8.2: "a unique identifier that is unique within the scope of the model instance"). Distinct from SACM-ID-001: `gid` is SACM's own model-global identifier rather than the XMI serialization id, and it is the handle third-party tools key on, so a document can be clean on one and broken on the other. An absent or empty (`""`) `gid` is not an identity and is not compared; every other value is compared exactly, letter case and white space included (D-GID-EMPTY). `validation::validate` reports one Error per repeated value, of elements of any kind, affecting every holder in document order, so a strict save refuses the document; reading and editing do not. `Code::GID_DUPLICATE` (SACM23-VAL-002). Fix: give each element its own `gid`, or remove the copies. |
| SACM-ID-004 | Info | An `xmi:id`, on an element, a `name`, or a `content`, `key` or `value` (ADR 0025), has XML white space (#x20, #x9, #xA, #xD) around an NCName. An `xmi:id` is an `xsd:ID`, whose white space is collapsed (XMI 2.5.1 §7.6.1; XML Schema 1.0 Part 2 §4.3.6), so `xmi::read` reads the trimmed value as the id, in both modes, and reports one Info per attribute at its name, quoting the value as read and affecting the trimmed id (for a `name`, `content`, `key` or `value`, the element that owns it). `xmi::write` writes the trimmed id. Nothing needs fixing. `Code::ID_TRIMMED` (SACM23-XMI-025, ADR 0024). |
| SACM-REF-001 | Error | Dangling reference: target ID does not resolve. A reference names no element of the document: an id absent from it, or the `xmi:id` of a `name`, `content`, `key` or `value`, which identifies no element. `xmi::read` keeps the reference in both modes and a tolerant `xmi::write` writes it back, so nothing is lost (ADR 0026); `validation::validate` reports one Error per distinct missing id of each reference end of each element, with the end's clause (8.2 for `citedElement` and `abstractForm`) and no location, affecting the referring element, then the missing id, so a strict save refuses the document. `Code::REF_DANGLING` (SACM23-VAL-003). Fix: point the reference at an element of the document, add the element it names, or remove the reference, in the file; edits that set flags and references are LIB-EDIT-008/009, not built yet. |
| SACM-REF-002 | Error | Reference resolves to an element of the wrong type. |
| SACM-REF-003 | Warning | Reference resolves to an element the document carries only as preserved compatibility content, so it cannot be type-checked. Distinct from SACM-REF-001: the target is present in the source, it is merely untyped. Conflating them reports an intact argument as structurally broken. |

## Validation

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-ENUM-001 | Error | Invalid literal: a value that is not one of its type's literals: an enumeration's, exactly, or an `xsd:boolean`'s. `xmi::read` refuses, in both modes, an `assertionDeclaration` that is not one of the six AssertionDeclaration literals (`asserted`, `needsSupport`, `assumed`, `axiomatic`, `defeated`, `asCited`; clause 11.8), as an attribute or an element, as `ReadError::InvalidLiteral`, holding the value as read and its location; it is never read as `asserted`. `Code::ENUM_INVALID_LITERAL` (SACM23-VAL-006, ADR 0021 amendment 2). It also refuses a Boolean that is not one of the `xsd:boolean` literals `true`, `false`, `1` and `0`, white space around them collapsed: an `isCitation` or `isAbstract` (clause 8.2) such as `TRUE`, `yes` or the empty value, as an attribute or an element; it is never read as false (SACM23-BASE-007, SACM23-BASE-008, ADR 0026). Fix: write the literal exactly, letter case included; for an enumeration, with no white space around it. |
| SACM-MULT-001 | Error / Warning | Multiplicity violation: a property held more or fewer times than its multiplicity allows. Error, for example: a ModelElement with no `name` (clause 8.6 `name:LangString[1]`; SACM23-VAL-018, `Code::MULTIPLICITY_VIOLATION`) or with two (SACM23-XMI-021), a `content` or `key` MultiLangString with no value (clause 8.5 `value:LangString[1..*]`) or with two values in one language (clause 8.5: each `lang` "must be unique"; compared exactly, so absent and `""` differ), a TaggedValue with no `key` (clause 8.12 `key:MultiLangString[1]`; all three SACM23-VAL-010, on the UtilityElement), an `AssertedRelationship` with no source (clause 11.13 `source[1..*]`) or not exactly one target (`target[1]`), or a binding with fewer than two participant packages; the AssertedRelationship and binding examples are reserved, and the rest is emitted. Warning: a ModelElement with two or more descriptions (SACM23-VAL-011; clause 8.6 text `description:Description[0..1]`, where the model says `0..*`, D-DESC-MULT); every description is kept, and a strict save is not refused. For input, `xmi::read` refuses a single-valued property given more than once as `ReadError::RepeatedValue`, giving every occurrence (SACM23-XMI-014): as an attribute and an element (XMI 2.5.1 §9.5.2 rule 2h), or as two or more elements, a second `name` included (SACM23-XMI-021), and so are a second `gid` (SACM23-BASE-006) and a second `content` or `key` (SACM23-BASE-004, SACM23-BASE-005). Fix: give the value once; for a MultiLangString, give it at least one value and one value per language; merge repeated descriptions into one. |
| SACM-CITE-001 | Error | An element has a `citedElement` but its `isCitation` is not true, against the clause 8.2 OCL constraint `self.citedElement <> null implies self.isCitation = true`. `validation::validate` reports one Error per such element, of any kind, affecting it, with no location, whether or not the cited id resolves (a dangling one is also SACM-REF-001). Clause 8.2 states only this direction, so `isCitation` true with no `citedElement` is no finding (ADR 0026). `Code::CITATION_INVALID` (SACM23-VAL-007). Fix: set `isCitation="true"`, or remove the `citedElement`, in the file; edits that set flags and references are LIB-EDIT-008/009, not built yet. |
| SACM-ABS-001 | Error / Warning | An `isAbstract`/`abstractForm` combination the standard rules out. Error: an abstract element using `abstractForm` (clause 8.2 gives it to concrete elements), or a concrete `Expression` referencing abstract `ExpressionElement`s (clause 10.10 OCL). Warning: the referred `abstractForm` target is not abstract, or is a different type — clause 8.2 words both with "should". Emitted: the clause 8.2 part, `Code::ABSTRACT_FORM_INVALID` (SACM23-VAL-008). `validation::validate` reports, for each element with an `abstractForm`, one Error when its own `isAbstract` is true, affecting the element, whatever the target; and, when the target is an element of the document, one Warning when the target is not abstract and one when it is of another kind, each affecting the element, then the target. A target that names no element gives only SACM-REF-001. The Errors make a strict save refuse; the Warnings do not. Fix: make the element concrete, or point the `abstractForm` at an abstract element of the same kind, in the file; edits that set flags and references are LIB-EDIT-008/009, not built yet. The clause 10.10 part is reserved. |
| SACM-EXPR-001 | Warning | An `ExpressionLangString` carries both an `expression` reference and literal `content`. Clause 8.4: "If expression is not empty, then +content should be empty." A warning because the clause says "should", but a real one: the two carry the same meaning twice and a reader has no rule for which wins. |
| SACM-PKG-001 | Error / Warning | Content the owning package clause does not allow. Error: an `ArgumentPackage` that nests an `ArgumentPackage` but contains something else (clause 11.4), interface or binding content that is not a citation (clauses 11.5, 11.6, 12.4, 12.5), or an `AssuranceCasePackageInterface` holding a non-interface sub-package (clause 9.3 OCL). Warning: an interface citation pointing outside the package it implements, and a binding named as another binding's participant — see the recorded resolutions in [decisions.md](decisions.md) (D-IFACE-CITE, D-BIND-PART), since the parallel clauses disagree. Emitted: the clause 11.4 Error (SACM23-VAL-012), `Code::PACKAGE_CONTENT_INVALID`. `validation::validate` reports, for each plain `ArgumentPackage` with a plain `ArgumentPackage` among its `argumentElement` children, one Error per other `argumentElement` child not of an `ArgumentPackage` kind, affecting the package, then the child; an `ArgumentPackageInterface` or `ArgumentPackageBinding` child neither triggers nor is reported, and UtilityElements are not counted (D-PKG-HOMOG). Fix: move those elements into a nested package. The interface, binding and OCL parts are reserved. |

## Commands

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-CMD-001 | Error | Operation target not found. `Code::CMD_TARGET_NOT_FOUND`, `EditError::ParentNotFound` (LIB-EDIT-001): a create operation names a parent id that is not in the document. Fix: create the parent first, or correct its id (ids are compared exactly). |
| SACM-CMD-002 | Error | Delete rejected: element is referenced and policy is `RejectIfReferenced`. |
| SACM-CMD-003 | Error | Preview expired: the document changed after the preview was taken. |
| SACM-CMD-004 | Error | Create rejected: caller-provided ID already exists. `Code::CMD_DUPLICATE_ID`, `EditError::DuplicateId` (LIB-EDIT-001). Ids are unique across the whole document. Fix: choose another id, or leave it out to have one generated. |
| SACM-CMD-005 | Error | Invalid parent: the target cannot contain the requested child kind. `Code::CMD_INVALID_PARENT`, `EditError::InvalidParent` (LIB-EDIT-001): the parent's class has no composite role for the new kind, such as a Claim directly in an AssuranceCasePackage. Fix: choose a parent that can hold the kind (a Claim goes in an ArgumentPackage). |
| SACM-CMD-006 | Error | Delete rejected: package is not empty and policy is `RejectIfNonEmpty`. |
| SACM-CMD-007 | Error | Delete rejected: external (cross-package) references exist and policy is `RejectIfExternalReferencesExist`. |
