# Diagnostics catalog

Machine-readable diagnostic codes emitted by the `sacm` crate. **Codes are stable API**:
once released, a code's meaning never changes and a retired code is never reused.

Every diagnostic carries: `code`, `severity` (info / warning / error), the matrix row
and clause it enforces, affected element ids, an optional source location
(line/column), a human-readable message, and the template and arguments the message is
made from (LIB-API-018). See decision D-DIAG. Every read and write refusal (`ReadError`, `WriteError`) carries a code too, and its message's template and
arguments (LIB-API-017): see [Message templates](#message-templates).

> **Status.** The codes below are adopted from the assurance-forge C++ SACM library (same
> author), so that the two implementations report the same finding with the same code.
> Tool-specific wording from that project ("Assurance Forge", ODE containers) has been kept
> where it explains the code. A row is *live* when its Meaning names the `Code::NAME`
> constant whose text is the row's code: the crate emits that code, and the row says which
> matrix rows emit it. A row naming no constant is *reserved*: the crate does not emit it
> yet. Where a live row describes more than the crate emits, it says which part is emitted
> and that the rest is reserved. A test (LIB-DIAG-002) checks that the live rows are
> exactly the crate's `Code` constants.

Adding a code: append the row here in the same change that adds its constant to the
crate, and name the matrix row that owns it.

## XML and security

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-XML-001 | Error | The input is not well-formed XML 1.0 with namespaces, is truncated, is not valid UTF-8 or UTF-16, declares ASCII but holds non-ASCII, or has a UTF-16 byte order mark but declares an encoding other than UTF-16, UTF-16LE or UTF-16BE. UTF-16 with a byte order mark is read. Fix: correct the XML at the reported location. `Code::XML_MALFORMED`, the code of `ReadError::Malformed` (LIB-SEC-002, LIB-SEC-005, SACM23-XMI-018). |
| SACM-SEC-001 | Error | The input has a DOCTYPE, which may declare entities; it is refused before it is read. Fix: remove the DOCTYPE, because SACM XMI does not need one. `Code::XML_DOCTYPE_REJECTED`, the code of `ReadError::Doctype` (LIB-SEC-001). |
| SACM-SEC-002 | Error | The input has more nodes, nesting levels, attributes or namespaces than the parser can hold, or an element the document could not hold, which checked input never gives. | SACM-XML-002 | Error | The input is in an encoding this version does not read: a byte order mark other than UTF-8's and UTF-16's, UTF-16 or UCS-4 without a mark, or a declared encoding other than UTF-8 and ASCII without a UTF-16 mark. Both modes refuse it as `ReadError::Unsupported`, with this code and the label `(a limit of this version)`. Fix: convert the file to UTF-8. `Code::XML_ENCODING_NOT_READ` (LIB-API-009, LIB-API-017). |
| SACM-XML-003 | Error | An element's id, gid, name, text or other string holds a character XML 1.0 cannot represent (one outside its `Char` production, such as U+0001), so the element cannot be written. ## Identity and references

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-ID-001 | Error | Duplicate element ID: two or more elements in the input carry the same `xmi:id` (XMI 2.5.1 §7.6.1), whether elements, `name`s, the `content`, `key` and `value` elements of a UtilityElement (ADR 0025), or a Resource's `location` and its `value`s (ADR 0034 amendment 1), compared by `xsd:ID` value (XML white space around an NCName trimmed, SACM23-XMI-025; ADR 0024). `xmi::read` refuses the input, giving the location of every element that carries the repeated `xmi:id`. `Code::ID_DUPLICATE`, `ReadError::DuplicateId` (SACM23-VAL-001). | SACM-ID-002 | Error | Invalid element ID syntax: an element's id is not an XML NCName (XMI 2.5.1 §7.6.1: `xmi:id` is an `xsd:ID`). `Code::ID_INVALID`. | SACM-ID-003 | Error | Duplicate `gid` (clause 8.2: "a unique identifier that is unique within the scope of the model instance"). Distinct from SACM-ID-001: `gid` is SACM's own model-global identifier rather than the XMI serialization id, and it is the handle third-party tools key on, so a document can be clean on one and broken on the other. Fix: give each element its own `gid`, or remove the copies. |
| SACM-ID-004 | Info | An `xmi:id`, on an element, a `name`, or a `content`, `key`, `location` or `value` (ADR 0025), has XML white space (#x20, #x9, #xA, #xD) around an NCName. ## Validation

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-ENUM-001 | Error (strict) / Warning (tolerant read) | Invalid literal: a value that is not one of its type's literals: an enumeration's, exactly, or an `xsd:boolean`'s. A strict `xmi::read` refuses an `assertionDeclaration` that is not one of the six AssertionDeclaration literals (`asserted`, `needsSupport`, `assumed`, `axiomatic`, `defeated`, `asCited`; clause 11.8), as an attribute or an element, as `ReadError::InvalidLiteral`, holding the value as read and its location; it is never read as `asserted`. `Code::ENUM_INVALID_LITERAL` (SACM23-VAL-006, ADR 0021 amendment 2). It also refuses a Boolean that is not one of the `xsd:boolean` literals `true`, `false`, `1` and `0`, white space around them collapsed: an `isCitation` or `isAbstract` (clause 8.2), or an `isCounter` (clause 11.13), such as `TRUE`, `yes` or the empty value, as an attribute or an element; it is never read as false (SACM23-BASE-007, SACM23-BASE-008, SACM23-ARG-007, ADR 0026). The same holds for the `xsi:nil` of a value element. A tolerant read keeps the attribute, or the value element whole, as preserved content, with one Warning at the strict refusal's location affecting the element, and holds the default: `asserted`, false, or the property absent for `xsi:nil`. The value counts as the property's first occurrence, so a later one is SACM-MULT-001; `SetAssertionDeclaration` and `SetFlag` replace a preserved attribute of their property's name (SACM23-VAL-006, ADR 0035). ## Message templates

Every diagnostic, and every read and write refusal, names the English sentence form of
its message by a stable template id, and gives the values the sentence is made from as
named arguments, so that an application can word the message in any language
(LIB-API-017, LIB-API-018; ADR 0030 amendment 3).

- **Ids.** A template id is `<CODE>/<form>`, such as `SACM-XMI-014/unread-kind`: the code
  of what carries it, then a form in lower-case words joined by `-`.
  `Diagnostic::template`, `ReadError::template` and `WriteError::template` return it, and
  `arguments` the arguments, in the order they first appear in the sentence.
- **Stability.** As for every serialized name (ADR 0030 amendment 1): renaming or removing
  a template id or an argument name, or changing an argument's kind or meaning, is
  breaking; adding a template, or an argument to a template, is not. The English is not
  promised.
- **Placeholders.** `{name}` writes a Text argument as it is and a Count in decimal,
  `{name:?}` writes a Text quoted as Rust's `{:?}` quotes it, and `{name:04X}` writes a
  Count as at least four upper-case hex digits. A Text argument is a string, a Count a
  non-negative integer.
- **Frames.** A diagnostic's `message` is the rendered sentence, with no frame; its
  `Display` adds the severity, code, row, clause and location (ADR 0011). A refusal's
  `Display` puts its variant's fixed frame around the rendered
  sentence: for `Malformed`, `the input is not well-formed XML`, the location and `: `
  first; for `Unsupported`, `the reader cannot represent the input`, the location and `: `
  first, and after it ` ` and the label of its code: `(a limit of this version; ROW
  reads it)` for SACM-XMI-014 and SACM-XMI-007, `(strict mode never reads it; ROW is to
  read it in tolerant mode)` for SACM-XMI-002 and SACM-XMI-015, where ROW is its `row`
  argument, `(a limit of this version)` for SACM-XML-002 and SACM-SEC-002, and `(a defect
  in the input)` for SACM-XMI-003; for `DuplicateId` and `RepeatedValue`, the locations
  after it; for `InvalidLiteral`, the location and `: ` and the literals of its property
  after it; for `LegacyShape`, `, a shape of the assurance-forge C++ library`, the location
  and `: a strict read refuses it; a tolerant read reads it as its standard form, which
  write writes` after it; for `MissingType`, the location and `: give it an xmi:type that
  names its class` after it; and for the other read refusals, the location after it. A
  write refusal's `Display` is the sentence.
- **No template.** A diagnostic built with `test-support`'s `Diagnostic::new`, or read from
  JSON that gives no template, as 0.1.0 wrote, has its code's text, such as
  `SACM-MULT-001`, as its template, and no arguments.
- **Records.** A refusal read back with serde must name one of its variant's templates,
  with that template's code and exactly its arguments, by name, kind and order; its
  `Display` renders them. A diagnostic read back gives `template` and `arguments`
  together or neither: one of its code's diagnostic templates with exactly its arguments,
  or its code's text with none. Its `message` is kept as given.
