# Diagnostics catalog

Machine-readable diagnostic codes emitted by the `sacm` crate. **Codes are stable API**:
once released, a code's meaning never changes and a retired code is never reused.

Every diagnostic carries: `code`, `severity` (info / warning / error), the matrix row and
clause it enforces, affected element ids, an optional source location (line/column), a
human-readable message, and the template and arguments the message is made from
(LIB-API-018). See decision D-DIAG. Every read and write refusal (`ReadError`,
`WriteError`) carries a code too, and its message's template and arguments (LIB-API-017):
see [Message templates](#message-templates).

> **Status.** The codes below are adopted from the assurance-forge C++ SACM library (same
> author), so that the two implementations report the same finding with the same code.
> Tool-specific wording from that project ("Assurance Forge", ODE containers) has been kept
> where it explains the code. A row is *live* when its Meaning names the `Code::NAME`
> constant whose text is the row's code: the crate emits that code, and the row says which
> matrix rows emit it. A row naming no constant is *reserved*: the crate does not emit it
> yet. Where a live row describes more than the crate emits, it says which part is emitted
> and that the rest is reserved. A test (LIB-DIAG-002) checks that the live rows are
> exactly the crate's `Code` constants.

Adding a code: append the row here in the same change that adds its constant to the
crate, and name the matrix row that owns it.

## XML and security

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-XML-001 | Error | The input is not well-formed XML 1.0 with namespaces, is truncated, is not valid UTF-8 or UTF-16, declares ASCII but holds non-ASCII, has a UTF-16 byte order mark but declares an encoding other than UTF-16, UTF-16LE or UTF-16BE, or has a UTF-8 byte order mark but declares ISO-8859-1. UTF-16 with a byte order mark, and ISO-8859-1 declared without a mark, are read. Fix: correct the XML at the reported location. `Code::XML_MALFORMED`, the code of `ReadError::Malformed` (LIB-SEC-002, LIB-SEC-005, SACM23-XMI-018). |
| SACM-SEC-001 | Error | The input has a DOCTYPE, which may declare entities; it is refused before it is read. Fix: remove the DOCTYPE, because SACM XMI does not need one. `Code::XML_DOCTYPE_REJECTED`, the code of `ReadError::Doctype` (LIB-SEC-001). |
| SACM-SEC-002 | Error | The input has more than 65,535 distinct namespace bindings, 2³² attributes, or more nodes than the parser can hold under a node limit of 2³² or more, or an element the document could not hold, which checked input never gives. Both modes refuse it as `ReadError::Unsupported`, with this code, the label `(a limit of this version)` and no location. `Code::PARSER_LIMIT` (LIB-API-011, LIB-API-017, LIB-SEC-003). |
| SACM-SEC-003 | Error | The input passes a limit of `ReadOptions::with_limits` (LIB-SEC-003): its size in bytes, the nesting depth of its elements (counted as resolved: a root that a same-file proxy moves takes the proxy's depth, and its tree shifts with it; SACM23-XMI-030), the XML nodes the parser builds, or the namespace bindings in scope at an element; the bindings that the elements declaring namespaces hold in scope count against the node limit. Everything else a read keeps besides the parsed tree counts against the size limit, in one budget: the namespace text that preserved content keeps (each kept URI and binding, as it is kept) and the text of each diagnostic the read emits (the bytes of its text arguments and of its affected ids, not its fixed message), as it is emitted. Both modes refuse it as `ReadError::LimitExceeded`, naming the limit and its value, at the element (or preserved construct, or diagnostic) where it passes, and with no location for the size and the node count. Fix: if the file is trusted, read it with higher `Limits`. `Code::LIMIT_EXCEEDED`. |
| SACM-XML-002 | Error | The input is in an encoding this version does not read: a byte order mark other than UTF-8's and UTF-16's, UTF-16 or UCS-4 without a mark, or a declared encoding other than UTF-8, ASCII and ISO-8859-1 without a UTF-16 mark. Both modes refuse it as `ReadError::Unsupported`, with this code and the label `(a limit of this version)`. Fix: convert the file to UTF-8. `Code::XML_ENCODING_NOT_READ` (LIB-API-009, LIB-API-017). |
| SACM-XML-003 | Error | An element's id, gid, name, text or other string holds a character XML 1.0 cannot represent (one outside its `Char` production, such as U+0001), so the element cannot be written. Both modes of `xmi::write` refuse it as `WriteError::UnrepresentableCharacter`. Fix: remove the character with an edit. `Code::XML_UNREPRESENTABLE_CHARACTER` (SACM23-XMI-011, LIB-API-017). |

## Identity and references

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-ID-001 | Error | Duplicate element ID: two or more elements in the input carry the same `xmi:id` (XMI 2.5.1 §7.6.1), whether elements, `name`s, the `content`, `key` and `value` elements of a UtilityElement (ADR 0025), or a Resource's `location` and its `value`s (ADR 0034 amendment 1), compared by `xsd:ID` value (XML white space around an NCName trimmed, SACM23-XMI-025; ADR 0024). `xmi::read` refuses the input, giving the location of every element that carries the repeated `xmi:id`. `Code::ID_DUPLICATE`, `ReadError::DuplicateId` (SACM23-VAL-001). Fix: give each element, `name`, `content`, `key`, `location` and `value` its own id, or leave out the id of a `name`, `content`, `key`, `location` or `value`. |
| SACM-ID-002 | Error | Invalid element ID syntax: an element's id is not an XML NCName (XMI 2.5.1 §7.6.1: `xmi:id` is an `xsd:ID`). `Code::ID_INVALID`. For a new element it is `EditError::InvalidId` (LIB-EDIT-001). A referenced id, given to a create, `SetReferences` or `AddReference` and not already held, that holds XML white space (#x20, #x9, #xA, #xD), such as the `a b` of an element read from a file, is `EditError::InvalidReference`, because it would be written as an IDREFS attribute of several ids (SACM23-ARG-005, SACM23-ARG-008, SACM23-ARG-010). A typed end never holds such an id, so `CopyElements` is never refused for one; a copied element whose own id is not an NCName gets a generated id (LIB-EDIT-018). For an id read from a file, on an element or on a `name`, `content`, `key`, `location` or `value`: an empty `xmi:id` is refused by a strict read as `ReadError::InvalidId`; a tolerant read reads such an element with a generated id, and such a part with none, with one Warning at its start tag affecting the generated id or the owner and no SACM-XMI-004, and keeps one inside preserved content as written, outside the id space, with one Warning affecting the holder (ADR 0035); an NCName with XML white space around it is read trimmed (SACM-ID-004); and any other id that is not an NCName (such as `1c`, `a:b` or `a b`) is read as written and reported by `validation::validate` (SACM23-VAL-020), and a strict save refuses the document (schema check, not `validate`; LIB-COMPAT-007, ADR 0035 D4). A name's `xmi:id`, and the `xmi:id` of a `content`, a `key`, a `location` or a `value` in one (ADR 0025), that is not an NCName is reported on the element that owns it. An `xmi:id` in XMI metadata, on or under `xmi:XMI` or in an element's or part's metadata, that is not an NCName is read as written; a strict save refuses it as `WriteError::Invalid` with `SACM-ID-002/metadata-id-not-an-ncname`, an Error with row SACM23-XMI-019 and clause 7.6.1, affecting the element that holds the metadata, if one does (ADR 0042). | SACM-ID-003 | Error | Duplicate `gid` (clause 8.2: "a unique identifier that is unique within the scope of the model instance"). Distinct from SACM-ID-001: `gid` is SACM's own model-global identifier rather than the XMI serialization id, and it is the handle third-party tools key on, so a document can be clean on one and broken on the other. An absent or empty (`""`) `gid` is not an identity and is not compared; every other value is compared exactly, letter case and white space included (D-GID-EMPTY). `validation::validate` reports one Error per repeated value, of elements of any kind, affecting every holder in document order, so a strict save refuses the document; reading and editing do not. `Code::GID_DUPLICATE` (SACM23-VAL-002). Fix: give each element its own `gid`, or remove the copies. |
| SACM-ID-004 | Info | An `xmi:id`, on an element, a `name`, or a `content`, `key`, `location` or `value` (ADR 0025), has XML white space (#x20, #x9, #xA, #xD) around an NCName. An `xmi:id` is an `xsd:ID`, whose white space is collapsed (XMI 2.5.1 §7.6.1; XML Schema 1.0 Part 2 §4.3.6), so `xmi::read` reads the trimmed value as the id, in both modes, and reports one Info per attribute at its name, quoting the value as read and affecting the trimmed id (for a `name`, `content`, `key`, `location` or `value`, the element that owns it). `xmi::write` writes the trimmed id. ## Message templates

Every diagnostic, and every read and write refusal, names the English sentence form of
its message by a stable template id, and gives the values the sentence is made from as
named arguments, so that an application can word the message in any language
(LIB-API-017, LIB-API-018; ADR 0030 amendment 3).

- **Ids.** A template id is `<CODE>/<form>`, such as `SACM-XMI-003/unread-attribute`: the code
  of what carries it, then a form in lower-case words joined by `-`.
  `Diagnostic::template`, `ReadError::template` and `WriteError::template` return it, and
  `arguments` the arguments, in the order they first appear in the sentence.
- **Stability.** As for every serialized name (ADR 0030 amendment 1): renaming or removing
  a template id or an argument name, or changing an argument's kind or meaning, is
  breaking; adding a template, or an argument to a template, is not. The English is not
  promised.
- **Placeholders.** `{name}` writes a Text argument as it is and a Count in decimal,
  `{name:?}` writes a Text quoted as Rust's `{:?}` quotes it, and `{name:04X}` writes a
  Count as at least four upper-case hex digits. A Text argument is a string, a Count a
  non-negative integer.
- **Frames.** A diagnostic's `message` is the rendered sentence, with no frame; its
  `Display` adds the severity, code, row, clause and location (ADR 0011). A refusal's
  `Display` puts its variant's fixed frame around the rendered
  sentence: for `Malformed`, `the input is not well-formed XML`, the location and `: `
  first; for `Unsupported`, `the reader cannot represent the input`, the location and `: `
  first, and after it ` ` and the label of its code: `(strict mode never reads it; ROW reads it
  in tolerant mode)` for SACM-XMI-002, SACM-XMI-008 and SACM-XMI-015, where ROW is its `row`
  argument, `(a limit of this version)` for SACM-XML-002, SACM-SEC-002, and SACM-XMI-008 and
  SACM-XMI-015 without a row, and `(a defect in the input)` for SACM-XMI-003; for `DuplicateId` and
  `RepeatedValue`, the locations
  after it; for `InvalidLiteral`, the location and `: ` and the literals of its property
  after it; for `LegacyShape`, `, a shape of the assurance-forge C++ library`, the location
  and `: a strict read refuses it; a tolerant read reads it as its standard form, which
  write writes` after it; for `MissingType`, the location and `: give it an xmi:type that
  names its class` after it; for `LimitExceeded`, the location after it; and for the other
  read refusals, the location after it. A
  write refusal's `Display` is the sentence.
- **No template.** A diagnostic built with `test-support`'s `Diagnostic::new`, or read from
  JSON that gives no template, as 0.1.0 wrote, has its code's text, such as
  `SACM-MULT-001`, as its template, and no arguments.
- **Records.** A refusal read back with serde must name one of its variant's templates,
  with that template's code and exactly its arguments, by name and kind; its `Display`
  renders them. A diagnostic read back gives `template` and `arguments` together or
  neither: one of its code's diagnostic templates with exactly its arguments, or its
  code's text with none. Its `message` is kept as given. `arguments` may give its keys in
  any order; they are read by name, held and written in the template's order. A missing,
  extra, repeated or wrongly typed argument is refused.
