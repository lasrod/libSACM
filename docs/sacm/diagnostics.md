# Diagnostics catalog

Machine-readable diagnostic codes emitted by the `sacm` crate. **Codes are stable API**:
once released, a code's meaning never changes and a retired code is never reused.

Every diagnostic carries: `code`, `severity` (info / warning / error), the matrix row
and clause it enforces, affected element ids, an optional source location
(line/column), and a human-readable message. See decision D-DIAG.

> **Status.** The codes below are adopted from the assurance-forge C++ SACM library (same
> author), so that the two implementations report the same finding with the same code.
> Tool-specific wording from that project ("Assurance Forge", ODE containers) has been kept
> where it explains the code. A row is *live* when its Meaning names the `Code::NAME`
> constant whose text is the row's code: the crate emits that code, and the row says which
> matrix rows emit it. A row naming no constant is *reserved*: the crate does not emit it
> yet. Where a live row describes more than the crate emits, it says which part is emitted
> and that the rest is reserved. A test (LIB-DIAG-002) checks that the live rows are
> exactly the crate's `Code` constants.

Adding a code: append the row here in the same change that adds its constant to the
crate, and name the matrix row that owns it.

## XML and security

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-XML-001 | Error | The input is not well-formed XML 1.0 with namespaces, is truncated, is not valid UTF-8 or UTF-16, declares ASCII but holds non-ASCII, or has a UTF-16 byte order mark but declares an encoding other than UTF-16, UTF-16LE or UTF-16BE. UTF-16 with a byte order mark is read. Fix: correct the XML at the reported location. `Code::XML_MALFORMED`, the code of `ReadError::Malformed` (LIB-SEC-002, LIB-SEC-005, SACM23-XMI-018). |
| SACM-SEC-001 | Error | The input has a DOCTYPE, which may declare entities; it is refused before it is read. Fix: remove the DOCTYPE, because SACM XMI does not need one. `Code::XML_DOCTYPE_REJECTED`, the code of `ReadError::Doctype` (LIB-SEC-001). |

## XMI structure

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-XMI-001 | Error | An interchange root (the document element, or an element child of the XMI element outside the XMI namespace) is not named as one of the twelve SACM package kinds, or the XMI element holds no root. Fix: make the document element, or each child of `xmi:XMI`, a SACM 2.3 package such as `sacm:AssuranceCasePackage` or `sacm:ArgumentPackage`; a single package needs no `xmi:XMI` element. `Code::XMI_INVALID_ROOT`, the code of `ReadError::InvalidRoot` and `ReadError::NoPackage` (SACM23-XMI-001). |
| SACM-XMI-002 | Error (strict) / Warning (tolerant) | Namespace URI is not a pinned SACM 2.3 namespace. A strict read refuses an unrecognised SACM-like namespace (LIB-COMPAT-004, a tolerance: strict mode never applies it, ADR 0022); the document is not called non-conformant for its namespace alone (D-NS-PIN). |
| SACM-XMI-003 | Error (strict) / Warning (tolerant) | Content that neither the SACM XML Schema nor the XMI 2.5.1 production rules allow where it stands, and that no row reads as a tolerance: an attribute the element's class lacks (a vendor attribute, `isCounter` on a Claim, `xmi:version` on a child, an empty `citedElement=""`), a child element in another namespace or under a role the class lacks, any child of a UtilityElement, a child whose type names no concrete class, is not admitted by its role or disagrees with its other type attribute, a defect inside a `name`, `content`, `key`, value or reference element (which keeps that whole child, and leaves the property absent), non-white-space text in element-only content, and a root's type naming another class. `xmi::read` keeps it exactly as written, in both modes, as preserved content of the element it sits in, and reports one per construct, at its attribute's name, start tag or first text character, affecting that element: a Warning in tolerant mode and an Error in strict mode. Nothing inside a preserved subtree is read or reported, but its `xmi:id`s are checked. A tolerant `xmi::write` writes it back where it stood; a strict one refuses it (SACM-XMI-006). Strict only: an attribute or text on the `xmi:XMI` element, and a preserved attribute whose prefix `sacm` or `xmi` is bound to another namespace, are refused as `ReadError::Unsupported`. A tolerant read keeps the first as the document's preserved content, outside every element, affecting no element, and the second under the first prefix `nsN` unbound at its element, which the message names (ADR 0035). Conforming content this version does not read yet is never this code: it is SACM-XMI-014 or SACM-XMI-007. `Code::XMI_UNKNOWN_CONTENT` (LIB-COMPAT-003, ADR 0033). Fix: remove the content, or keep it in an `xmi:Extension` once SACM23-XMI-019 reads one. |
| SACM-XMI-004 | Info | An element has no `xmi:id`, which XMI 2.5.1 §7.6.1 makes optional (`use="optional"`). `xmi::read` reads it in both modes, a root or a child, with a generated id in the edit scheme `<snake_case kind>_<n>` that no `xmi:id` in the input holds, and reports one Info per element at its start tag, affecting the generated id. The generated id is an ordinary id: `xmi::write` writes it, and later edits generate above it. Nothing needs fixing. `Code::XMI_MISSING_ID` (SACM23-XMI-020, ADR 0024). |
| SACM-XMI-005 | Error (strict) / Warning (tolerant read) | Containment role has an abstract declared type and the child carries no type attribute (`xmi:type`, or `xsi:type` on import) and no `xmi:idref` or `href`, such as an `<argumentElement>` with none in an ArgumentPackage. The child's element name is its role, so no class can be inferred (XMI 2.5.1 §7.6.3), and none is guessed: a strict `xmi::read` refuses it as `ReadError::MissingType`, at its start tag. A tolerant read keeps the child whole as preserved content of its parent, its `xmi:id`s in the id space, with one Warning at its start tag affecting the parent (LIB-COMPAT-001, ADR 0035). An element in reference form is a proxy not read yet (SACM23-XMI-019, SACM23-XMI-027), not this code. Fix: give the child an `xmi:type` naming its class, such as `xmi:type="sacm:Claim"`. An untyped role element with `xlink:href` or `xmi:href` is rightly this code, because only an unqualified `href` is a reference form (XMI.xsd `LinkAttribs`). `Code::XMI_MISSING_TYPE` (LIB-COMPAT-010, ADR 0022 amendment 1). |
| SACM-XMI-006 | Error | Strict save refused: the document holds preserved content (such as SACM-XMI-003, SACM-XMI-007, SACM-XMI-013 from a strict read, and SACM-XMI-014), and the writer cannot show that content it did not read is schema-valid. A strict `xmi::write` returns `WriteError::PreservedContent`, listing each element that holds it once, in document order, before the schema check; `elements` is empty when only the document holds content, outside every element (ADR 0035 D3). It never omits the content. Display: `the document cannot be written in strict mode: the element "p" holds preserved content`, `…: 4 elements hold preserved content, the first is "p"`, or `…: the document holds preserved content outside its elements`. A tolerant write writes it. `Code::XMI_STRICT_SAVE_REFUSED` (SACM23-XMI-008, ADR 0033, ADR 0035). Fix: write in tolerant mode, or delete the elements that hold the content. Content the document holds outside its elements can be written only in tolerant mode in this release. |
| SACM-XMI-007 | Warning | External (cross-document) `href` reference is not supported yet; kept as preserved content in tolerant mode only. A tolerant `xmi::read` keeps a reference element whose `href` has a document part (such as `other.xmi#c9`) or that carries `XLink` attributes, or a role element in reference form with an `href`, whole, as preserved content of its element, with one Warning at the strict refusal's location affecting that element; the reference end stays empty. A strict read refuses it as `ReadError::Unsupported`, and a strict write refuses a document that holds it (SACM-XMI-006). It is never SACM-XMI-003: such a reference conforms. `Code::XMI_EXTERNAL_HREF` (LIB-API-011, ADR 0035; SACM23-XMI-027 reads it). |
| SACM-XMI-008 | Warning | Document declares a SACM revision other than 2.3; loaded in compatibility mode by a tolerant read. A strict read refuses it (LIB-COMPAT-004, a tolerance: strict mode never applies it, ADR 0022). Distinct from SACM-XMI-002, which means the namespace itself is unrecognized. |
| SACM-XMI-009 | Warning | The document's root is not a SACM interchange package, but SACM packages were found inside it (an ODE `DDIPackage`, say). A tolerant load reads the SACM out and states that the file does not conform, that content outside the SACM packages is not represented, and that saving writes conformant SACM rather than the original container. Strict refuses the document (SACM-XMI-001). |
| SACM-XMI-010 | Error (strict) / Warning (tolerant) | An `xsi:type` attribute is used; XMI 2.5.1 §9.5.2 rule 2g allows it only if `org.omg.xmi.useSchemaExtensions` is true, and SACM sets no such tag. The document is read as if it were `xmi:type`. Fix: write `xmi:type`. `Code::XMI_XSI_TYPE` (LIB-COMPAT-001, ADR 0022). |
| SACM-XMI-011 | Info | An `xmi:version` attribute on the `xmi:XMI` element or a root is present and ignored: the XMI namespace identifies the version (XMI 2.5.1 §7.5.3). Nothing is lost and nothing needs fixing. To silence it, remove the attribute, or save the document again with `xmi::write`, which does not write it. `Code::XMI_VERSION_IGNORED` (LIB-COMPAT-001, ADR 0022). |
| SACM-XMI-012 | Error (strict) / Warning (tolerant) | A name or a text is written in a shape of the assurance-forge C++ library that maps one to one onto its standard form: a `name="…"` attribute on a ModelElement (read as the name's `content`, `lang` absent); text as the `content` of a `name` or `value`; a `name` holding one `value`, or one `content` carrying `lang`; the single-language shorthand of a `content` or `key` (`content` and `lang` attributes, or text, with no `value`), read as a MultiLangString of one value; `content=` (with an optional `lang=`) or text on a UtilityElement; and `key=` and `value=` on a `taggedValue` (its `key` and its `content`). A tolerant `xmi::read` reads each as its standard form, values exactly (absent is not `""`, nothing trimmed), with one Warning per occurrence, located at the shape's first attribute, else its first text character that is not white space, else the `<` of a `value` in a `name`, and affecting the element. A strict read refuses the first shape as `ReadError::LegacyShape`, once the rest of the input has read without a refusal. A field given both in a shape and in the standard form, or twice, is `ReadError::RepeatedValue` (SACM-MULT-001) in both modes. Both saves write the standard form. Shapes that invent or merge elements, such as a `name` holding several entries, stay refused (LIB-COMPAT-012). Fix: read the file in tolerant mode and save it again. `Code::XMI_LEGACY_SHAPE` (LIB-COMPAT-008, ADR 0022 amendment 1). |
| SACM-XMI-013 | Error (strict) / Warning (tolerant) | A name spelled where formal/23-05-08 and ptc/22-03-13 disagree and the crate follows the other (D-TEXT-MODEL): the type `ArtifactAssertedRelationship` under a role that admits an ArtifactAssetRelationship, an Event's `occurece`, and `argumentationElement` as an ArgumentPackage's role or an ArgumentGroup's end. A tolerant `xmi::read` reads it as the resolved name, with one Warning per construct read, at its start tag or attribute name, affecting the element the spelling belongs to; a value given under both names is read from the resolved name and the spelled one is a repeat (SACM-MULT-001). A strict read keeps the construct as preserved content of the element it sits in, with one Error, so a strict write refuses the document (SACM-XMI-006). `xmi::write` writes the resolved names. Fix: read the file in tolerant mode and save it again. `Code::XMI_SPELLING_VARIANT` (SACM23-XMI-009). |
| SACM-XMI-014 | Warning | Content this release does not read yet, which a tolerant `xmi::read` keeps as preserved content: an element of a kind not read yet (such as an `ArtifactPackageInterface`, as a child, or a `TerminologyPackage`, as a child or a root), a package's `interface` end, a `name` or `value` typed `ExpressionLangString`, or XMI metadata (such as `xmi:uuid`, `xmi:label`, `xsi:schemaLocation`, `xmi:Documentation` or `xmi:Extension`). It is not a defect: its message ends `; ROW reads it`, naming the row that reads it. One Warning per construct, at the strict refusal's location, affecting the element that holds it, or no element for content on or under `xmi:XMI`, which the document holds outside its elements. A strict read refuses it as `ReadError::Unsupported`, and a strict write refuses a document that holds it (SACM-XMI-006). `Code::XMI_UNREAD_CONTENT` (LIB-API-011, ADR 0035). |

## Identity and references

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-ID-001 | Error | Duplicate element ID: two or more elements in the input carry the same `xmi:id` (XMI 2.5.1 §7.6.1), whether elements, `name`s, the `content`, `key` and `value` elements of a UtilityElement (ADR 0025), or a Resource's `location` and its `value`s (ADR 0034 amendment 1), compared by `xsd:ID` value (XML white space around an NCName trimmed, SACM23-XMI-025; ADR 0024). `xmi::read` refuses the input, giving the location of every element that carries the repeated `xmi:id`. `Code::ID_DUPLICATE`, `ReadError::DuplicateId` (SACM23-VAL-001). Fix: give each element, `name`, `content`, `key`, `location` and `value` its own id, or leave out the id of a `name`, `content`, `key`, `location` or `value`. |
| SACM-ID-002 | Error | Invalid element ID syntax: an element's id is not an XML NCName (XMI 2.5.1 §7.6.1: `xmi:id` is an `xsd:ID`). `Code::ID_INVALID`. For a new element it is `EditError::InvalidId` (LIB-EDIT-001). A referenced id, given to a create, `SetReferences` or `AddReference` and not already held, that holds XML white space (#x20, #x9, #xA, #xD), such as the `a b` of an element read from a file, is `EditError::InvalidReference`, because it would be written as an IDREFS attribute of several ids (SACM23-ARG-005, SACM23-ARG-008, SACM23-ARG-010). A typed end never holds such an id, so `CopyElements` is never refused for one; a copied element whose own id is not an NCName gets a generated id (LIB-EDIT-018). For an id read from a file, on an element or on a `name`, `content`, `key`, `location` or `value`: an empty `xmi:id` is refused by a strict read as `ReadError::InvalidId`; a tolerant read reads such an element with a generated id, and such a part with none, with one Warning at its start tag affecting the generated id or the owner and no SACM-XMI-004, and keeps one inside preserved content as written, outside the id space, with one Warning affecting the holder (ADR 0035); an NCName with XML white space around it is read trimmed (SACM-ID-004); and any other id that is not an NCName (such as `1c`, `a:b` or `a b`) is read as written and reported by `validation::validate` (SACM23-VAL-020), and a strict save refuses the document (schema check, not `validate`; LIB-COMPAT-007, ADR 0035 D4). A name's `xmi:id`, and the `xmi:id` of a `content`, a `key`, a `location` or a `value` in one (ADR 0025), that is not an NCName is reported on the element that owns it. Fix: use a name that starts with a letter or `_` and has no spaces or `:`, or leave the id out to have one generated. |
| SACM-ID-003 | Error | Duplicate `gid` (clause 8.2: "a unique identifier that is unique within the scope of the model instance"). Distinct from SACM-ID-001: `gid` is SACM's own model-global identifier rather than the XMI serialization id, and it is the handle third-party tools key on, so a document can be clean on one and broken on the other. An absent or empty (`""`) `gid` is not an identity and is not compared; every other value is compared exactly, letter case and white space included (D-GID-EMPTY). `validation::validate` reports one Error per repeated value, of elements of any kind, affecting every holder in document order, so a strict save refuses the document; reading and editing do not. `Code::GID_DUPLICATE` (SACM23-VAL-002). Fix: give each element its own `gid`, or remove the copies. |
| SACM-ID-004 | Info | An `xmi:id`, on an element, a `name`, or a `content`, `key`, `location` or `value` (ADR 0025), has XML white space (#x20, #x9, #xA, #xD) around an NCName. An `xmi:id` is an `xsd:ID`, whose white space is collapsed (XMI 2.5.1 §7.6.1; XML Schema 1.0 Part 2 §4.3.6), so `xmi::read` reads the trimmed value as the id, in both modes, and reports one Info per attribute at its name, quoting the value as read and affecting the trimmed id (for a `name`, `content`, `key`, `location` or `value`, the element that owns it). `xmi::write` writes the trimmed id. Nothing needs fixing. `Code::ID_TRIMMED` (SACM23-XMI-025, ADR 0024). |
| SACM-REF-001 | Error | Dangling reference: target ID does not resolve. A reference names no element of the document: an id absent from it, or the `xmi:id` of a `name`, `content`, `key`, `location` or `value`, which identifies no element. `xmi::read` keeps the reference in both modes and a tolerant `xmi::write` writes it back, so nothing is lost (ADR 0026); `validation::validate` reports one Error per distinct missing id of each reference end of each element, with the end's clause (8.2 for `citedElement` and `abstractForm`, 11.2 for an ArgumentGroup's `argumentElement`, 11.9 for `referencedArtifactElement`, 11.10 for `metaClaim`, 11.12 for `structure`, 11.13 for `reasoning`, `source` and `target`, 12.3 for an ArtifactGroup's `artifactElement`, 12.14 for an ArtifactAssetRelationship's `source` and `target`) and no location, affecting the referring element, then the missing id. A strict save refuses a reference that names no `xmi:id` the output writes (schema check, not `validate`; LIB-COMPAT-007, ADR 0035 D4): it writes a reference to a name's `xmi:id`, which `validate` still reports. An id that a multi-valued end (`metaClaim`, `source`, `referencedArtifactElement`, a group's `argumentElement` or `artifactElement`, an ArtifactAssetRelationship's `target`) holds twice is one finding (ADR 0027). No edit makes a dangling reference: a create operation, `SetReferences`, `AddReference` or `CopyElements` refuses an id that names no element as SACM-CMD-001, except an id the end already holds, which a set keeps (ADR 0029); `MoveElement` changes no reference (ADR 0036). `Code::REF_DANGLING` (SACM23-VAL-003, SACM23-ART-010). Fix: point the reference at an element of the document, add the element it names, or remove the reference, in the file or with `SetReferences` or `RemoveReference` (LIB-EDIT-009). |
| SACM-REF-002 | Error | Reference resolves to an element of the wrong type. `validation::validate` reports one Error per distinct id of each reference end of each element that names an element whose kind the end's declared type (ptc/22-03-13) does not admit, such as a `metaClaim` naming an ArgumentReasoning, with the end's clause (8.2, 11.2, 11.9, 11.10, 11.12, 11.13, 12.3 or 12.14, where an ArtifactAssetRelationship's `source` and `target` admit only ArtifactAssets) and no location, affecting the referring element, then the target (SACM23-VAL-004); and one Error per distinct source of an AssertedEvidence (clause 11.15 OCL), or source or target of an AssertedArtifactSupport (clause 11.17) or AssertedArtifactContext (clause 11.18), that is an ArgumentAsset but not an ArtifactReference, with that clause (SACM23-VAL-016). A dangling id is only SACM-REF-001, and a reference SACM23-VAL-004 reports is not reported again by SACM23-VAL-016. `xmi::read` keeps such a reference in both modes and a tolerant `xmi::write` writes it back; a strict save refuses the document. No edit makes a wrongly typed reference: a create operation, `SetReferences`, `AddReference` or `CopyElements` refuses an id its end's declared type does not admit as `EditError::WrongReferenceType`, after every id is found to exist, except an id the end already holds (ADR 0029; a copy checks every reference of the copies, against the target and the copies, ADR 0036); the clause 11.15, 11.17 and 11.18 rules are content, which no edit refuses (D-VAL-LAYER, ADR 0028). `Code::REF_WRONG_TYPE` (SACM23-VAL-004, SACM23-VAL-016, SACM23-ART-010). Fix: point the reference at an element of the end's type, in the file or with `SetReferences`. |
| SACM-REF-003 | Warning | Reference resolves to an element the document carries only as preserved content (SACM-XMI-003), so it cannot be type-checked. Distinct from SACM-REF-001: the target is present in the source, it is merely untyped. Conflating them reports an intact argument as structurally broken. `validation::validate` reports one Warning per distinct such id of each reference end of each element, with the end's clause and no location, affecting the referring element, then the id; never SACM-REF-001 or SACM-REF-002 for it. A strict save is not refused for it (it is refused for the preserved content). `Code::REF_PRESERVED_TARGET` (LIB-COMPAT-003, ADR 0033). Fix: point the reference at an element of the document, or make the target SACM 2.3. |

## Validation

| Code | Severity | Meaning |
| --- | --- | --- |
| SACM-ENUM-001 | Error (strict) / Warning (tolerant read) | Invalid literal: a value that is not one of its type's literals: an enumeration's, exactly, or an `xsd:boolean`'s. A strict `xmi::read` refuses an `assertionDeclaration` that is not one of the six AssertionDeclaration literals (`asserted`, `needsSupport`, `assumed`, `axiomatic`, `defeated`, `asCited`; clause 11.8), as an attribute or an element, as `ReadError::InvalidLiteral`, holding the value as read and its location; it is never read as `asserted`. `Code::ENUM_INVALID_LITERAL` (SACM23-VAL-006, ADR 0021 amendment 2). It also refuses a Boolean that is not one of the `xsd:boolean` literals `true`, `false`, `1` and `0`, white space around them collapsed: an `isCitation` or `isAbstract` (clause 8.2), or an `isCounter` (clause 11.13), such as `TRUE`, `yes` or the empty value, as an attribute or an element; it is never read as false (SACM23-BASE-007, SACM23-BASE-008, SACM23-ARG-007, ADR 0026). The same holds for the `xsi:nil` of a value element. A tolerant read keeps the attribute, or the value element whole, as preserved content, with one Warning at the strict refusal's location affecting the element, and holds the default: `asserted`, false, or the property absent for `xsi:nil`. The value counts as the property's first occurrence, so a later one is SACM-MULT-001; `SetAssertionDeclaration` and `SetFlag` replace a preserved attribute of their property's name (SACM23-VAL-006, ADR 0035). Fix: write the literal exactly, letter case included; for an enumeration, with no white space around it. |
| SACM-MULT-001 | Error / Warning | Multiplicity violation: a property held more or fewer times than its multiplicity allows. Error, for example: a ModelElement with no `name` (clause 8.6 `name:LangString[1]`; SACM23-VAL-018, `Code::MULTIPLICITY_VIOLATION`) or with two (SACM23-XMI-021), a `content`, `key` or `location` (clause 12.10) MultiLangString with no value (clause 8.5 `value:LangString[1..*]`) or with two values in one language (clause 8.5: each `lang` "must be unique"; compared exactly, so absent and `""` differ), a TaggedValue with no `key` (clause 8.12 `key:MultiLangString[1]`; all three SACM23-VAL-010, on the element that holds the role; an absent `location` gives none), an `AssertedRelationship` with no source (clause 11.13 `source:ArgumentAsset[1..*]`) or no target (`target:ArgumentAsset[1]`), one Error per missing end on the relationship (SACM23-VAL-005; a second target is refused on read as `ReadError::RepeatedValue`, ADR 0027), an ArtifactAssetRelationship with no source (clause 12.14 `source:ArtifactAsset[1..*]`) or no target (`target:ArtifactAsset[1..*]`), one Error per missing end (SACM23-ART-010), or a binding with fewer than two participant packages; the binding example is reserved, and the rest is emitted. A create operation refuses an `AssertedRelationship` with no source, and an ArtifactAssetRelationship with no source or no target, as `EditError::TooFewReferences` (SACM23-ARG-008, SACM23-ARG-010, SACM23-ART-010), and so do the reference edits that would leave a relationship with no source or no target: `SetReferences` with no `source`, `SetReferences::clear` of the `target`, and `RemoveReference` of the last source or of the target (LIB-EDIT-009). They refuse an end given more ids than it allows, two on a single-valued end such as `target` or `reasoning`, or an `AddReference` to one that holds an id, as `EditError::TooManyReferences` (LIB-EDIT-009, ADR 0029). `CopyElements` refuses to copy an `AssertedRelationship` or an ArtifactAssetRelationship with no source or no target as `EditError::TooFewReferences` (LIB-EDIT-018). The document is unchanged. Warning: a ModelElement with two or more descriptions (SACM23-VAL-011; clause 8.6 text `description:Description[0..1]`, where the model says `0..*`, D-DESC-MULT); every description is kept, and a strict save is not refused. Warning, too: an id that one multi-valued reference end (`metaClaim`, clause 11.10; `source`, clause 11.13; `referencedArtifactElement`, clause 11.9; an ArgumentGroup's `argumentElement`, clause 11.2; an ArtifactGroup's `artifactElement`, clause 12.3; an ArtifactAssetRelationship's `source` and `target`, clause 12.14) of one element holds two or more times, whose values are unique in ptc/22-03-13 (no `isUnique`, so the UML default); one Warning per repeated id, with the end's clause and no location, affecting the element, then the id, reported whatever else applies to the id (SACM23-VAL-022). The repeat is kept as read, and a strict save is not refused. For input, a strict `xmi::read` refuses a single-valued property given more than once as `ReadError::RepeatedValue`, giving every occurrence (SACM23-XMI-014): as an attribute and an element (XMI 2.5.1 §9.5.2 rule 2h), or as two or more elements, a second `name` included (SACM23-XMI-021), and so are a second `gid` (SACM23-BASE-006), a second `content`, `key` or `location` (SACM23-BASE-004, SACM23-BASE-005, SACM23-ART-005), a second `version`, `date`, `startTime` or `endTime` (SACM23-ART-002, SACM23-ART-004), and two ids or a second element on a single-valued reference end; a multi-valued end (`metaClaim`, `source`, `referencedArtifactElement`, an ArgumentGroup's `argumentElement`, an ArtifactGroup's `artifactElement`, an ArtifactAssetRelationship's `target`) given both as an attribute and as elements is refused the same way (ADR 0027, ADR 0034). A tolerant read reads the first occurrence and keeps each later one as preserved content, with one Warning at it affecting the element; two ids in the attribute of a single-valued end keep the whole attribute, with one Warning at the second id, and the end holds none; a repeat inside a `name`, `content`, `key`, `location` or `value` keeps that whole part, with one Warning at the second occurrence (LIB-COMPAT-001, ADR 0035). Fix: give the value once; give every relationship a source and a target; for a MultiLangString, give it at least one value and one value per language; merge repeated descriptions into one; remove a repeated id from a reference end. |
| SACM-CITE-001 | Error | An element has a `citedElement` but its `isCitation` is not true, against the clause 8.2 OCL constraint `self.citedElement <> null implies self.isCitation = true`. `validation::validate` reports one Error per such element, of any kind, affecting it, with no location, whether or not the cited id resolves (a dangling one is also SACM-REF-001). Clause 8.2 states only this direction, so `isCitation` true with no `citedElement` is no finding (ADR 0026). `Code::CITATION_INVALID` (SACM23-VAL-007). Fix: set `isCitation="true"` (`SetFlag`, LIB-EDIT-008), or remove the `citedElement` (`SetReferences::clear`, LIB-EDIT-009), in the file or with an edit. An edit does not refuse either one alone (ADR 0029). |
| SACM-CITE-002 | Warning | An Assertion declared `asCited` is not a citation of an Assertion. Clause 11.8 says asCited means "because the Assertion is cited, the AssertionDeclaration should be transitively derived from the value of the AssertionDeclaration of the cited Assertion". `validation::validate` reports, for each element of an Assertion kind (a Claim or an asserted relationship) whose `assertionDeclaration` is `asCited`, with clause 11.8 and no location: one Warning when its `isCitation` is not true, affecting it; one when its `citedElement` is absent, affecting it; and one when its `citedElement` names an element of the document that is not of an Assertion kind, affecting it, then that element. A `citedElement` that names no element gives only SACM-REF-001. The element is kept, and a strict save is not refused. `Code::AS_CITED_INVALID` (SACM23-VAL-019). Fix: make the element a citation of a Claim or an asserted relationship (`SetFlag`, `SetReferences`), or give it another declaration (`SetAssertionDeclaration`). |
| SACM-ABS-001 | Error / Warning | An `isAbstract`/`abstractForm` combination the standard rules out. Error: an abstract element using `abstractForm` (clause 8.2 gives it to concrete elements), an `implementationConstraint` on an element whose `isAbstract` is not true (clause 8.6 OCL `implementationConstraint->size() > 0 implies isAbstract = true`, spelled `implmentationConstraint` there, spec defect D15), or a concrete `Expression` referencing abstract `ExpressionElement`s (clause 10.10 OCL). Warning: the referred `abstractForm` target is not abstract, or is a different type — clause 8.2 words both with "should". Emitted: the clause 8.2 and 8.6 parts, `Code::ABSTRACT_FORM_INVALID` (SACM23-VAL-008, SACM23-VAL-021). `validation::validate` reports each ModelElement with one or more `implementationConstraint` children whose `isAbstract` is not true as one Error, with clause 8.6, affecting it, however many constraints it has; reading and editing do not refuse it (SACM23-VAL-021). `validation::validate` reports, for each element with an `abstractForm`, one Error when its own `isAbstract` is true, affecting the element, whatever the target; and, when the target is an element of the document, one Warning when the target is not abstract and one when it is of another kind, each affecting the element, then the target. A target that names no element gives only SACM-REF-001. The Errors make a strict save refuse; the Warnings do not. Fix: for a constraint, set `isAbstract="true"` or remove the constraints; for an `abstractForm`, make the element concrete (`SetFlag`, LIB-EDIT-008), or point the `abstractForm` at an abstract element of the same kind (`SetReferences`, LIB-EDIT-009), in the file or with an edit; an edit does not refuse either one (ADR 0029). The clause 10.10 part is reserved. |
| SACM-EXPR-001 | Warning | An `ExpressionLangString` carries both an `expression` reference and literal `content`. Clause 8.4: "If expression is not empty, then +content should be empty." A warning because the clause says "should", but a real one: the two carry the same meaning twice and a reader has no rule for which wins. |
| SACM-PKG-001 | Error / Warning | Content the owning package clause does not allow. Error: an `ArgumentPackage` that nests an `ArgumentPackage` but contains something else (clause 11.4), interface or binding content that is not a citation (clauses 11.5, 11.6, 12.4, 12.5), or an `AssuranceCasePackageInterface` holding a non-interface sub-package (clause 9.3 OCL). Warning: an interface citation pointing outside the package it implements, and a binding named as another binding's participant — see the recorded resolutions in [decisions.md](decisions.md) (D-IFACE-CITE, D-BIND-PART), since the parallel clauses disagree. Emitted: the clause 11.4 Error (SACM23-VAL-012), `Code::PACKAGE_CONTENT_INVALID`. `validation::validate` reports, for each plain `ArgumentPackage` with a plain `ArgumentPackage` among its `argumentElement` children, one Error per other `argumentElement` child not of an `ArgumentPackage` kind, affecting the package, then the child; an `ArgumentPackageInterface` or `ArgumentPackageBinding` child neither triggers nor is reported, and UtilityElements are not counted (D-PKG-HOMOG). Fix: move those elements into a nested package. The interface, binding and OCL parts are reserved. |
